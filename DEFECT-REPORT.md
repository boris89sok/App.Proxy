# Defect Report

Defects found in the supplied repository: the existing `App.MinimalApi` code and the supplied SQL script.
Each one was fixed at its root cause. The Region sample endpoints (`MinimalEndpoints`, `MyService`, `RegionService`, `GenericDataService`, the `NORTHWND` context, and the AutoMapper profile) were later **removed** because they are outside the scope of the specification. So was the unused Refit client (`ExternalService/IServicesApiClient`, an empty interface that nothing called, with `HttpClientExtension`, `RawLoggingHandler` and the `AppSettings:{Env}:ApiUrl` configuration). Their defects remain listed because they were present in the supplied code; the rows say "Resolved by removal". The **Test** column names the automated test that demonstrates the fix. Where an automated test doesn't fit (host or configuration wiring), the column says how the fix was verified.

## Issues found and fixed while implementing the proxy

These weren't in the supplied code, but they're recorded because they're security-relevant:

- **Hop-by-hop nomination.** A header listed by the caller in `Connection:` must never be forwarded, even when it's allowlisted (RFC 9110 §7.6.1). Test: `Allowlisted_header_nominated_as_hop_by_hop_by_the_caller_is_not_forwarded`.
- **Implicit `traceparent`.** `HttpClient` added W3C trace headers to upstream calls. This was found in the end-to-end run against the mock destination. It's turned off with `ActivityHeadersPropagator = NoOutput`, so only allowlisted headers and `X-Correlation-Id` leave the proxy.
- **Partial credentials returned 403 instead of 401.** With two independent schemes, a single valid credential produced "authenticated but forbidden". Replaced with a composite scheme that succeeds only when both succeed. Tests: `AuthenticationTests.*`.
- **Routing-level 415.** `Accepts("application/json")` made routing reject other content types with an empty body, bypassing the proxy's error contract and audit. Tests: `Invalid_content_type_is_rejected`.
